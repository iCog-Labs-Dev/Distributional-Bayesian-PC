## Scope and code map

The reusable implementation lives in [`bpcn/`](../bpcn/). Experiment-specific
orchestration lives in [`experiments/`](../experiments/). The experiment files
consume the refactored package APIs; core modules do not import experiment
code.

```text
bpcn/
├── __init__.py                 top-level public API
├── checkpoints.py              strict checkpoint save/load
├── configs/
│   └── base.py                 validated immutable configuration
├── data/
│   ├── types.py                DatasetSplit, Targets, and Batch
│   ├── moments.py              Gaussian logit target construction
│   └── mnist.py                MNIST splits and minibatches
├── models/
│   ├── layer.py                Bayesian linear layer
│   ├── network.py              network construction and JAX pytree support
│   ├── moments.py              predictive moment propagation
│   └── activations.py          activation samples and moment approximations
├── losses/
│   ├── distributional_kl.py    Gaussian inclusion-KL terms
│   ├── categorical.py          mean and Monte Carlo categorical losses
│   └── weight_kl.py            posterior-to-prior weight KL
├── inference/
│   ├── state.py                latent moment state
│   ├── shared_energy.py        energy shared by inference and training
│   └── e_step.py               supervised and target-free latent inference
├── training/
│   ├── gradients.py            analytical Gaussian-layer gradients
│   ├── m_step.py               hidden and output layer updates
│   ├── loop.py                 JIT-compiled minibatch step
│   └── metrics.py              concise streaming epoch summaries
├── evaluation/
│   ├── predict.py              target-free prediction and evaluation
│   └── metrics.py              entropy and variance decomposition
├── utils/
│   └── safe_math.py            variance floors and log-variance limits
└── tests/                       core unit and characterization tests

experiments/
├── _artifacts.py               strict atomic JSON writer
├── mnist.py                    one-shot full-MNIST training
├── ood_eval.py                 one-shot rotated-MNIST evaluation
├── linear_gaussian.py          fixed 24-cell calibration experiment
└── tests/                       experiment contract and synthetic tests
```

Files under `__pycache__/` are generated bytecode and are not part of the
supported experiment surface.

The package has three interface levels:

1. [`bpcn/__init__.py`](../bpcn/__init__.py) exports the primary application
   API.
2. Subpackage `__init__.py` files expose useful lower-level records and
   functions for diagnostics and controlled tests.
3. Underscore-prefixed functions are implementation details. Experiments may
   use their own private helpers internally, but external code should not treat
   those helpers as stable interfaces.

## Runtime structure

Training alternates one latent inference phase with one or more weight-update
phases for each minibatch. Evaluation uses target-free latent inference and
does not expose labels to the latent state.

```text
BPCNConfig
    |
    v
initialize_network ----------> Network
                                  |
DatasetSplit -> Batch ------------+
                                  |
                                  v
                         supervised E-step
                         weights held fixed
                                  |
                                  v
                         inferred LatentState
                                  |
                                  v
                       repeated layerwise M-steps
                       latent state held fixed
                                  |
                                  v
                         updated Network + metrics
                                  |
                    +-------------+-------------+
                    |                           |
                    v                           v
             save_checkpoint            target-free inference
                                                |
                                                v
                                      mean and MC predictions
```

The main invariants are:

- A `Network` contains one Bayesian layer for every adjacent pair in
  `ModelConfig.layer_dims`.
- Every hidden layer has one matching latent mean and variance array.
- The E-step stops gradients through the network.
- The M-step consumes a stopped latent state and updates layer parameters.
- Weight posterior variances and latent variances remain diagonal.
- Residual variances and prior standard deviations are fixed layer attributes;
  training updates only weight means and weight log variances.
- Evaluation infers latents without targets and produces both Monte Carlo and
  posterior-mean probabilities.

### Minimal public API example

The following synthetic categorical batch exercises the intended top-level
training interface without importing private helpers:

```python
import jax
import jax.numpy as jnp

from bpcn import (
    BPCNConfig,
    Batch,
    InferenceConfig,
    ModelConfig,
    UpdateConfig,
    initialize_network,
    make_batch_step,
)

labels = jnp.asarray([0, 1, 2, 1], dtype=jnp.int32)
target_mean = jax.nn.one_hot(labels, 3, dtype=jnp.float32)
batch = Batch(
    inputs=jnp.ones((4, 5), dtype=jnp.float32),
    class_indices=labels,
    target_mean=target_mean,
    target_variance=jnp.full_like(target_mean, 1e-3),
)

config = BPCNConfig(
    model=ModelConfig(
        input_dim=5,
        hidden_dims=(8,),
        output_dim=3,
        activations=("tanh",),
    ),
    inference=InferenceConfig(
        steps=2,
        initial_mean_perturbation_std=0.0,
    ),
    update=UpdateConfig(steps=1, training_mc_samples=1),
)

network = initialize_network(jax.random.PRNGKey(0), config.model)
batch_step = make_batch_step(config, training_set_size=4)
result = batch_step(network, batch, jax.random.PRNGKey(1))
network = result.network
```

`result` also exposes the stopped latent state, E-step energy trace, per-layer
update metrics, and decomposed post-update energy.

## Configuration

All core configuration classes are frozen dataclasses defined in
[`bpcn/configs/base.py`](../bpcn/configs/base.py). Invalid values fail during
construction rather than later inside a compiled training step. Lists supplied
for tuple fields are normalized to tuples.

### `ModelConfig`

| Field | Default | Contract and effect |
| --- | --- | --- |
| `input_dim` | `784` | Positive input width. |
| `hidden_dims` | `(128,)` | Nonempty tuple of positive hidden widths. |
| `output_dim` | `2` | Positive output width. |
| `activations` | `("relu",)` | One activation per hidden layer. Choices: `identity`, `relu`, `leaky_relu`, `tanh`. |
| `initial_weight_log_variance` | `-6.0` | Finite initial value used by the `constant` prior scheme. |
| `hidden_log_variance_offset` | `0.0` | Finite value added to each hidden layer's selected initial log variance. |
| `hidden_initializer` | `"xavier"` | Hidden weight-mean initializer: `xavier` or `he`. |
| `output_initializer` | `"xavier"` | Output weight-mean initializer: `xavier` or `he`. |
| `hidden_prior_std` | `1.0` | Positive hidden prior standard deviation for `constant`. |
| `output_prior_std` | `1.0` | Positive output prior standard deviation for `constant`. |
| `hidden_residual_variance` | `1e-2` | Positive fixed residual variance for every hidden unit. |
| `output_residual_variance` | `1e-2` | Positive fixed residual variance for every output unit. |
| `prior_scheme` | `"matched_he"` | `constant`, `matched_he`, or `matched_xavier`. |
| `output_likelihood` | `"categorical"` | `categorical` or `gaussian`. |
| `output_estimator` | `"mc"` | `mean` or `mc`; selects the categorical training objective. |

`layer_dims` returns `(input_dim, *hidden_dims, output_dim)`, and
`hidden_layer_count` returns the number of configured hidden widths.

The prior scheme controls both the prior standard deviation and initial
posterior log variance:

- `constant` uses `hidden_prior_std`, `output_prior_std`, and
  `initial_weight_log_variance` directly.
- `matched_he` derives prior and posterior initialization from twice the
  inverse fan-in.
- `matched_xavier` derives them from the inverse fan-in.

The weight-mean initializer is independent of the prior scheme. Xavier uses an
inverse-fan-in scale; He uses twice that variance. The hidden log-variance
offset is applied after the scheme has chosen the base value and never applies
to the output layer.

### `InferenceConfig`

| Field | Default | Contract and effect |
| --- | --- | --- |
| `steps` | `20` | Positive number of latent-gradient steps. |
| `mean_learning_rate` | `0.1` | Positive gradient-descent rate for latent means. |
| `log_variance_learning_rate` | `0.05` | Positive gradient-descent rate for latent log variances. |
| `initial_variance` | `1e-2` | Positive lower reference used during latent initialization. |
| `initial_mean_perturbation_std` | `0.1` | Nonnegative scale for initialization noise. |

### `UpdateConfig`

| Field | Default | Contract and effect |
| --- | --- | --- |
| `steps` | `16` | Positive number of repeated M-steps per inferred minibatch. |
| `hidden_mean_learning_rate` | `1e-2` | Nonnegative hidden weight-mean rate. |
| `hidden_log_variance_learning_rate` | `5e-2` | Nonnegative hidden weight-log-variance rate. |
| `output_mean_learning_rate` | `1e-2` | Nonnegative output weight-mean rate. |
| `output_log_variance_learning_rate` | `5e-3` | Nonnegative output weight-log-variance rate. |
| `hidden_weight_kl_scale` | `0.1` | Nonnegative hidden weight-variance KL scale and fallback mean scale. |
| `output_weight_kl_scale` | `1.0` | Nonnegative output weight-variance KL scale and fallback mean scale. |
| `hidden_mean_kl_scale` | `0.004` | Optional nonnegative override for hidden weight-mean KL. |
| `output_mean_kl_scale` | `0.004` | Optional nonnegative override for output weight-mean KL. |
| `training_mc_samples` | `1` | Positive sample count for categorical MC training. |
| `output_loss_weight` | `1.0` | Positive multiplier on supervised output energy. |

Zero learning rates are valid and are used by the linear-Gaussian experiment
to freeze one layer. Setting a mean KL scale to `None` makes it fall back to
the corresponding `*_weight_kl_scale`; zero is an explicit override and does
not trigger the fallback.

### `EvaluationConfig`

| Field | Default | Contract and effect |
| --- | --- | --- |
| `inference` | `None` | Optional complete `InferenceConfig` used only for evaluation. |
| `mc_samples` | `16` | Positive number of predictive MC samples. |
| `batch_size` | `128` | Positive evaluation batch size. |

When `inference` is `None`, `resolve_inference` copies the training inference
steps, learning rates, and initial variance but sets
`initial_mean_perturbation_std` to `0.0`. Evaluation is therefore deterministic
at latent initialization unless an explicit evaluation inference configuration
requests perturbation.

### `BPCNConfig`

`BPCNConfig` contains exactly four fields—`model`, `inference`, `update`, and
`evaluation`—each with its corresponding default configuration. It is the
configuration passed to training, supervised inference, prediction, and
checkpoint I/O.

## Data contracts and minibatches

The generic records are defined in
[`bpcn/data/types.py`](../bpcn/data/types.py).

### `DatasetSplit`

| Field | Typical shape | Meaning |
| --- | --- | --- |
| `inputs` | `(sample_count, input_dim)` | Input features. |
| `labels` | `(sample_count,)` | Original dataset labels. |
| `class_indices` | `(sample_count,)` | Zero-based indices relative to the selected class order. |

`class_indices`, rather than `labels`, drive target construction and
classification metrics. For a requested class order such as `(7, 2, 9)`, the
corresponding class indices are `0`, `1`, and `2`.

### `Targets`

| Field | Typical shape | Meaning |
| --- | --- | --- |
| `mean` | `(batch_size, output_dim)` | Gaussian target means or auxiliary moments. |
| `variance` | `(batch_size, output_dim)` | Positive diagonal target variances. |
| `class_indices` | `(batch_size,)` or `None` | Required by categorical inference and updates. |

Gaussian output training uses `mean` and `variance`. Categorical output
training uses `class_indices`, although batches still carry target moments so
the same record works for both output likelihoods.

### `Batch`

`Batch` stores `inputs`, `class_indices`, `target_mean`, and
`target_variance`. Its `targets` property constructs a `Targets` view without
copying the underlying values.

### Target moments

[`gaussian_logit_targets`](../bpcn/data/moments.py) accepts a one-dimensional
class-index array and produces:

- a scaled one-hot target-mean matrix with `float32` dtype; and
- a same-shaped constant target-variance matrix with `float32` dtype.

The class count must be positive, the variance and scale must be strictly
positive, and all indices must lie inside the configured class range.

### MNIST splits and minibatches

[`load_mnist_split`](../bpcn/data/mnist.py) uses the standard first 60,000
samples for training and the following 10,000 for testing by default. It:

- filters to the requested unique class tuple;
- preserves original labels in `labels`;
- remaps them to contiguous `class_indices` according to tuple order; and
- shuffles only the training split using the supplied seed.

Raw arrays are cached within the Python process after their first load.

`iter_minibatches` optionally shuffles sample indices with `shuffle_seed` and
constructs target moments for each batch. Its default `drop_last=True` omits a
partial final batch. With `drop_last=False`, that final batch is included.
`count_batches` applies the same full-batch/remainder counting rule.

## Bayesian layers and moment propagation

### `Layer`

[`Layer`](../bpcn/models/layer.py) is a `NamedTuple` with the following layout:

| Field | Shape | Meaning |
| --- | --- | --- |
| `mean` | `(output_dim, input_dim)` | Weight-posterior mean. |
| `log_variance` | `(output_dim, input_dim)` | Diagonal weight-posterior log variance. |
| `residual_variance` | `(output_dim,)` | Fixed per-output residual variance. |
| `prior_std` | scalar `float` | Fixed zero-mean Gaussian prior standard deviation. |

`weight_variance()` exponentiates `log_variance`. `input_dim` and `output_dim`
are derived from the mean matrix shape.

### `Network`

[`Network`](../bpcn/models/network.py) stores:

- `layers`: all hidden Bayesian layers followed by one output layer;
- `hidden_activations`: exactly one name per hidden layer;
- `output_likelihood`: `gaussian` or `categorical`; and
- `output_estimator`: `mean` or `mc`.

`hidden_layer_count` is `len(layers) - 1`, and `output_layer` returns the final
layer. The network is registered as a JAX pytree. Layer arrays are dynamic
pytree children; activation and output-mode strings are static metadata. A
change to that metadata can therefore cause a separate JIT compilation.

`initialize_network` splits one key into one key per layer, resolves the prior
scheme, initializes all hidden layers, and appends the output layer. It does
not add bias vectors; every mapping is a matrix multiplication.

### Activation handling

[`bpcn/models/activations.py`](../bpcn/models/activations.py) has two paths:

- `activation_moments` propagates diagonal moments through a local
  first-order approximation.
- `apply_activation_sample` applies the actual activation to sampled latent
  values during Monte Carlo operations.

| Activation | Moment behavior |
| --- | --- |
| `identity` | Mean and variance pass through unchanged. |
| `relu` | The mean sign selects an active derivative of one or zero. |
| `leaky_relu` | Uses slope `1.0` for positive means and `0.01` otherwise; variance follows the squared slope. |
| `tanh` | Applies `tanh` to the mean and scales variance by the squared local derivative. |

These are local diagonal approximations, not exact transformed-distribution
moments.

### Predictive moments

[`moment_forward`](../bpcn/models/moments.py) returns a `PredictiveMoments`
record containing a batch of predictive means and variances. The predictive
mean is the input mean passed through the weight mean. Predictive variance is
the sum of three components:

| Component | Interpretation |
| --- | --- |
| `residual` | Fixed layer noise from `Layer.residual_variance`. |
| `propagated` | Input variance transported through squared weight means. |
| `epistemic` | Weight-posterior variance scaled by the input second moment. |

`variance_components` exposes those three arrays independently. The residual
component has one value per output unit; propagated and epistemic components
have one row per example.

## Losses and shared energy

### Gaussian distributional matching

[`gaussian_kl`](../bpcn/losses/distributional_kl.py) evaluates a per-unit
Gaussian inclusion-KL from target moments to predictive moments. It returns:

- `value`: the per-unit KL value;
- `mean_error`: target mean minus predictive mean;
- `variance_residual`: target variance plus squared mean error minus
  predictive variance; and
- `predictive_variance`: the numerically floored predictive variance used in
  denominators.

The residual is important to the weight log-variance update: positive values
request more predictive variance, while negative values request less.

### Categorical output losses

[`bpcn/losses/categorical.py`](../bpcn/losses/categorical.py) implements two
training estimators:

- `mean` activates the top latent mean, uses the output weight mean, and
  computes mean categorical negative log-likelihood.
- `mc` samples both the top latent and output weights, computes per-example
  negative log-likelihood for each draw, and averages across samples and the
  batch.

The MC training objective averages negative log-likelihoods from sampled
models. Predictive evaluation instead averages sampled probability vectors;
the two averaging operations are intentionally different.

### Weight-prior KL

[`gaussian_weight_kl_components`](../bpcn/losses/weight_kl.py) separates the
diagonal-Gaussian posterior-to-prior KL into:

- a mean-displacement component; and
- a posterior-variance component.

This separation allows the mean KL and variance KL to use different scales.
`gaussian_weight_kl` returns their sum per weight.

### Shared energy

[`bpcn/inference/shared_energy.py`](../bpcn/inference/shared_energy.py)
centralizes the energy used by inference, training summaries, and both output
likelihoods.

`presynaptic_moments` returns deterministic inputs for the first hidden layer
and activated latent moments for later layers. Hidden transition energy sums
the Gaussian matching KL between every hidden latent posterior and its
layerwise predictive distribution.

Output energy is:

- Gaussian moment matching for a Gaussian output likelihood; or
- categorical mean/MC negative log-likelihood for a categorical output
  likelihood.

`latent_free_energy` includes hidden transitions and, when targets are
provided, the weighted output energy. Target-free inference omits the output
term entirely.

`full_energy_terms` returns an `EnergyTerms` record:

| Field | Meaning |
| --- | --- |
| `output` | Weighted output loss. |
| `transitions` | Sum of hidden transition matching terms. |
| `weight_mean_kl` | Scaled prior penalty for weight means. |
| `weight_variance_kl` | Scaled prior penalty for weight variances. |
| `weight_kl` | Property returning both weight components. |
| `total` | Property returning output, transitions, and total weight KL. |

## Latent inference

[`bpcn/inference/e_step.py`](../bpcn/inference/e_step.py) implements the
E-step. A `LatentState` contains tuples of means and variances, one tuple entry
per hidden layer. `top_mean` and `top_variance` return the final hidden state.

### Initialization

Latents are initialized by a forward moment pass:

1. Input variance begins at zero.
2. Each hidden layer produces predictive mean and variance.
3. The predictive mean initializes that layer's latent mean.
4. The predictive variance, bounded below by `initial_variance`, initializes
   latent log variance.
5. For deeper networks, activated moments become the next layer's inputs.

When `initial_mean_perturbation_std` is nonzero, independent layer-specific
noise is scaled by predictive uncertainty and added to the initial means.

### Optimization and gradient boundary

The complete network is passed through `jax.lax.stop_gradient` before the
latent objective is formed. Gradients are taken only with respect to tuples of
latent means and log variances. Each step:

- evaluates the shared latent free energy;
- subtracts the configured mean gradient;
- subtracts the configured log-variance gradient;
- clamps latent log variances to the supported numerical range; and
- records the updated energy in a `jax.lax.scan` trace.

The final latent means and variances are also stopped before being returned,
which enforces the intended E-step/M-step separation.

If no key is supplied to the private shared inference path, key zero is used.
A valid configuration always has at least one step, allowing the first and
last trace entries to be reported safely.

### Inference entry points

`infer_latents(network, inputs, targets, config, key)` performs supervised
inference. Categorical networks require `targets.class_indices`; Gaussian
networks use target mean and variance.

`infer_target_free(network, inputs, inference_config, key=None)` optimizes only
hidden transition energy. It is the prediction path and accepts no targets.

Both return `EStepResult`:

- `latents`: final stopped `LatentState`;
- `metrics.initial_energy`: energy at initialization;
- `metrics.final_energy`: energy after the last step; and
- `metrics.energy_trace`: one value per inference step.

## Weight updates and training

### Analytical Gaussian-layer gradients

[`compute_layer_gradients`](../bpcn/training/gradients.py) computes the update
direction for Gaussian distributional matching. The returned
`LayerGradientTerms` retains:

- predictive moments and input second moments;
- mean error and variance residual;
- data and prior contributions for the mean;
- data and prior contributions for log variance; and
- the summed mean and log-variance update directions.

`data_scale` scales the minibatch matching contribution. `prior_scale` scales
the weight-prior contribution. `weight_kl_scale` controls the variance KL and
is also the default mean KL scale unless `mean_kl_scale` is explicitly given.

`apply_layer_update` adds the configured learning-rate-scaled analytical
direction to the mean and log variance, then clamps log variance. Residual
variance and prior standard deviation are copied unchanged. Its pre-update
loss reuses the predictive moments already returned by
`compute_layer_gradients`; only the updated layer requires another
`moment_forward` call.

### Layer update metrics

Every layer update returns concise health metrics while retaining enough
detail for programmatic diagnosis:

| Group | Fields |
| --- | --- |
| Single update loss | `data_loss_before`, `data_loss_after`, `data_loss_delta` |
| Repeated-loop loss | `loop_data_loss_before`, `loop_data_loss_after`, `loop_data_loss_delta` |
| Prior and gradients | `weight_kl` plus total, data, and prior gradient norms for mean and log variance |
| Variance state | `mean_weight_variance`, `positive_variance_residual_fraction`, `mean_abs_residual`, `log_variance_clamp_fraction` |
| Numerical state | `finite` |

For categorical output updates, `mean_abs_residual` stores the post-update
categorical loss and `positive_variance_residual_fraction` is zero because
there is no Gaussian output variance residual.

### Complete M-step

[`m_step`](../bpcn/training/m_step.py) updates each layer once while keeping the
inferred latent state fixed:

- Hidden layers always use the analytical Gaussian matching update against
  their corresponding latent moments.
- A Gaussian output layer uses the same analytical update against target
  moments.
- A categorical output layer differentiates the categorical objective with
  respect to output mean and log variance and applies gradient descent.

Categorical output training requires class indices. The returned `MStepResult`
contains a new `Network` and one `LayerUpdateMetrics` record per layer.

### Fused minibatch step

[`make_batch_step`](../bpcn/training/loop.py) accepts a complete configuration
and positive training-set size, then returns a JIT-compiled function with the
signature:

```python
batch_step(network, batch, key) -> BatchStepResult
```

For every call it:

1. sets data scale to the inverse actual batch size;
2. sets prior scale to the inverse full training-set size;
3. runs supervised inference once;
4. runs `UpdateConfig.steps` M-steps against the same stopped latent state;
5. summarizes the first and last update metrics for each layer; and
6. evaluates decomposed energy using the final network and fixed latent state.

`BatchStepResult` contains the updated network, inferred latents, E-step
metrics, per-layer update metrics, and `energy_after`.

### Epoch summaries

[`EpochMetricsAccumulator`](../bpcn/training/metrics.py) streams scalar values
without retaining per-batch records. `summary()` fails on an empty epoch and
otherwise returns an immutable `EpochSummary` containing:

- `batch_count`;
- average initial and final E-step energy plus their delta;
- average total, output, transition, and weight-KL energy;
- average absolute hidden variance residual;
- maximum log-variance clamp fraction seen in any layer; and
- `all_finite`, accumulated across layers and scalar metrics.

`to_dict()` produces the mapping stored by the MNIST history artifact.

## Prediction and evaluation

[`bpcn/evaluation/predict.py`](../bpcn/evaluation/predict.py) evaluates a
network without exposing targets to latent inference.

### Probability paths

Both prediction paths first infer hidden latents with `infer_target_free`:

- **Posterior mean:** activates the top latent mean, applies the output weight
  mean, and takes softmax.
- **Monte Carlo:** samples the top latent and output weight posterior,
  calculates softmax for each draw, and averages probability vectors.

The prediction code applies softmax for all supported MNIST variants. The
Gaussian-logit variant therefore uses its Gaussian outputs as classification
logits during evaluation.

MC prediction explicitly samples the output layer and top latent state. Hidden
weight uncertainty influences the inferred latent moments through predictive
moment propagation; hidden weight matrices are not separately sampled inside
the final MC probability function. Fixed output residual variance is also not
sampled when classification probabilities are formed.

For each evaluation batch, the caller's key remains the MC sampling key. A
role-specific latent-inference key is derived with `jax.random.fold_in(key, 0)`
and passed to `infer_target_free`. This preserves the established MC stream
while making an explicitly configured nonzero evaluation perturbation
reproducible from the caller's key. The default zero-perturbation evaluation
path is unchanged.

### Complete-split processing

`predict_split` and `evaluate_split`:

- resolve the evaluation inference configuration;
- reject nonpositive batch sizes and empty splits;
- pad the split to a complete static batch grid;
- use a mask to exclude padding from metrics; and
- process batches with a JIT-compiled `jax.lax.scan`.

`predict_split` removes padded rows and returns two NumPy matrices in a
`PredictionResult`:

- `mc_probabilities`; and
- `mean_probabilities`.

Both have shape `(sample_count, output_dim)`.

`evaluate_split` returns:

| Field | Meaning |
| --- | --- |
| `sample_count` | Number of real, unpadded examples. |
| `mc_accuracy` | Accuracy from averaged MC probabilities. |
| `mc_log_likelihood` | Average log probability of the true class. |
| `mc_entropy_mean`, `mc_entropy_std` | Predictive entropy summary. |
| `mean_accuracy` | Accuracy from posterior-mean probabilities. |
| `mean_log_likelihood` | Average true-class log probability. |
| `mean_entropy_mean`, `mean_entropy_std` | Posterior-mean entropy summary. |

The log-likelihood fields are normally negative. Negating them produces NLL,
which is why the experiment log lines display
`-metrics.mc_log_likelihood` and `-metrics.mean_log_likelihood`.

[`bpcn/evaluation/metrics.py`](../bpcn/evaluation/metrics.py) also exposes:

- `predictive_entropy`, which clips probabilities before taking logs; and
- `summarize_variance`, which reports totals and fractions for residual,
  propagated, and epistemic variance at a selected layer.

## Checkpoint format

[`bpcn/checkpoints.py`](../bpcn/checkpoints.py) defines schema version `1`.
One checkpoint is a directory containing exactly the two required checkpoint
files; experiment-specific JSON files may coexist beside them.

```text
run_directory/
├── checkpoint.json
└── weights.npz
```

### `checkpoint.json`

The manifest has exactly three top-level keys:

```json
{
  "schema_version": 1,
  "config": {
    "model": {},
    "inference": {},
    "update": {},
    "evaluation": {}
  },
  "metadata": {}
}
```

`config` is the dataclass representation of `BPCNConfig`. An explicit nested
evaluation inference configuration is reconstructed as `InferenceConfig` on
load. Metadata must be a JSON object; `save_checkpoint` accepts any mapping
whose converted dictionary is JSON serializable.

### `weights.npz`

For every zero-based layer index, the archive contains exactly:

```text
layer_<index>_mean
layer_<index>_log_variance
layer_<index>_residual_variance
layer_<index>_prior_std
```

Object arrays are not allowed. Unknown or missing array names cause loading to
fail.

### Validation

Before saving and after loading, checkpoint validation checks:

- layer count and every weight/residual shape;
- activation tuple, output likelihood, and output estimator;
- finiteness of all parameter arrays;
- positivity of residual variances and prior standard deviations;
- exact agreement of residual variances with `ModelConfig`; and
- agreement of layer prior standard deviations with the configured prior
  scheme.

The manifest rejects unknown or missing top-level keys, unsupported schema
versions, and malformed configuration sections. The loader supports only the
current schema; it does not reinterpret earlier experiment formats.

Checkpoint JSON and NPZ files are each written through a temporary file and
atomically replaced. `save_checkpoint` creates the destination directory if
needed and replaces its checkpoint files if they already exist. Experiment
runners add their own new-directory protections where appropriate.

`load_checkpoint` returns `Checkpoint(config, network, metadata)`.

## Numerical safeguards

[`bpcn/utils/safe_math.py`](../bpcn/utils/safe_math.py) centralizes numerical
bounds:

| Constant | Value | Use |
| --- | --- | --- |
| `MIN_VARIANCE` | `1e-8` | Floor for variances used by Gaussian matching. |
| `MIN_WEIGHT_LOG_VARIANCE` | `-12.0` | Lower weight log-variance limit. |
| `MAX_WEIGHT_LOG_VARIANCE` | `6.0` | Upper weight log-variance limit. |
| `MIN_LATENT_LOG_VARIANCE` | `-12.0` | Lower latent log-variance limit. |
| `MAX_LATENT_LOG_VARIANCE` | `6.0` | Upper latent log-variance limit. |

Weight log variances are clamped during initialization and after each update.
Latent log variances are clamped after each inference step. Layer metrics
report the fraction of weight values at either clamp boundary and whether the
updated layer remains finite.

## Full-MNIST experiment

[`experiments/mnist.py`](../experiments/mnist.py) is the only supported MNIST
training runner. It always uses all ten classes with a 60,000-example training
split, a 10,000-example test split, input width 784, and output width 10.

### Editable settings

The settings block is near the top of the file:

```python
MNIST_VARIANT = MNISTVariant.CATEGORICAL_MC

MLP_LAYERS = (
    (128, "relu"),
)

BATCH_SIZE = 128
EPOCHS = 5
EVALUATE_EVERY = 1
SEED = 0
EVALUATION_MC_SAMPLES = 16
RUN_DIR = Path("runs/mnist_full")

INFERENCE = InferenceConfig()
UPDATE = UpdateConfig()
```

`MLP_LAYERS` is a nonempty tuple of `(neuron_count, activation)` pairs. Widths
must be positive integers, and activations must be `identity`, `relu`,
`leaky_relu`, or `tanh`. For example:

```python
MLP_LAYERS = (
    (256, "relu"),
    (128, "tanh"),
)
```

This resolves to model dimensions `(784, 256, 128, 10)` with hidden
activations `("relu", "tanh")`. Model settings not selected by the experiment
retain `ModelConfig` defaults.

`INFERENCE` and `UPDATE` are grouped core configurations. To change latent
steps or the MLP update behavior, construct them directly in the same block:

```python
INFERENCE = InferenceConfig(
    steps=30,
    mean_learning_rate=0.08,
    log_variance_learning_rate=0.04,
)

UPDATE = UpdateConfig(
    steps=12,
    hidden_mean_learning_rate=8e-3,
    output_mean_learning_rate=8e-3,
)
```

`EXPERIMENT` is constructed from the settings block when the module is
imported. Edit the variables before starting the Python process; changing a
module variable afterward does not rebuild the existing `EXPERIMENT` object.

`MNISTExperimentConfig` also contains Gaussian target defaults used to build
all batches:

| Field | Default |
| --- | --- |
| `gaussian_target_variance` | `1e-3` |
| `gaussian_target_scale` | `1.0` |

They can be overridden explicitly in the `EXPERIMENT` constructor if a
Gaussian-logit protocol requires it.

### Variants

| `MNISTVariant` | Output likelihood | Training estimator |
| --- | --- | --- |
| `CATEGORICAL_MC` / `"categorical_mc"` | `categorical` | `mc` |
| `CATEGORICAL_MEAN` / `"categorical_mean"` | `categorical` | `mean` |
| `GAUSSIAN_LOGITS` / `"gaussian_logits"` | `gaussian` | `mean` |

All variants are evaluated as ten-class predictions with both MC and
posterior-mean softmax probabilities.

### Run flow

`run(settings)` performs computation without saving artifacts:

1. Resolve one internally consistent `BPCNConfig`.
2. Load and verify the fixed full-MNIST split sizes.
3. Split the root seed into initialization, training, and evaluation keys.
4. Initialize the configured network.
5. Build one JIT-compiled batch step using training-set size 60,000.
6. Train each epoch with full batches and a deterministic epoch-specific
   shuffle seed.
7. Evaluate every `evaluate_every` epochs and always evaluate the final epoch.
8. Return the final network, configuration, epoch records, and final metrics.

Each batch key is derived from the training key, epoch, and batch index.
Evaluation uses an epoch-folded evaluation key. The final epoch cannot finish
without evaluation; absence of final metrics raises an internal error.

### Logging

The runner uses concise `INFO` messages:

- data-loading start;
- selected variant, architecture, and split sizes;
- epoch number and total energy;
- MC/mean accuracy and NLL on evaluation epochs;
- energy delta and finite status on unevaluated epochs; and
- final artifact directory.

Per-batch traces and per-weight diagnostics are not logged. Essential training
health is accumulated in each epoch record.

### Saving

`save_run(settings, result)` writes:

```text
RUN_DIR/
├── checkpoint.json
├── weights.npz
└── history.json
```

The checkpoint metadata records:

- experiment name and experiment schema version;
- selected variant;
- fixed dataset identity, classes, sample counts, and dimensions;
- MLP layer pairs;
- batch size, epochs, evaluation frequency, seed, evaluation MC samples, and
  Gaussian target settings; and
- final evaluation metrics.

`history.json` contains schema version, experiment name, variant, one concise
record per epoch, and final evaluation metrics. An epoch's `evaluation` value
is `null` when that epoch was not scheduled for evaluation.

`ensure_new_run_directory` permits a missing or empty path and rejects an
existing nonempty path. There is no resume behavior, and the main runner never
overwrites an existing populated run directory.

## Rotated-MNIST OOD evaluation

[`experiments/ood_eval.py`](../experiments/ood_eval.py) evaluates one supported
MNIST checkpoint on a fixed rotation protocol. The only user-edited setting is:

```python
MNIST_RUN_DIR = Path("runs/mnist_full")
```

Point this value at the directory containing the MNIST `checkpoint.json` and
`weights.npz` files.

### Source validation

Before evaluation, the runner requires checkpoint metadata with:

- `experiment == "mnist"`;
- MNIST experiment schema version `1`;
- one of the three supported variant names; and
- the exact full-MNIST dataset record: classes 0 through 9, train size 60,000,
  test size 10,000, input width 784, and output width 10.

The loaded model dimensions must also be 784 and 10. This prevents a partial
class run, unrelated checkpoint, or older metadata shape from being evaluated
as the supported OOD protocol.

### Linear-Gaussian fixed protocol

| Setting | Value |
| --- | --- |
| Rotations in degrees | `0, 15, 30, 45, 60, 90, 135, 180` |
| Evaluation seed | `123` |
| Batch size | `256` |
| MC samples | `16` |
| ECE bins | `15` |
| Primary prediction | Monte Carlo |
| Diagnostic prediction | Posterior mean |

Zero degrees is required to be the first entry and supplies the in-distribution
baseline. A zero-degree transform returns the original values exactly.
Nonzero rotations preserve flattened `(sample_count, 784)` shape, preserve the
28-by-28 support, use constant zero outside the image, and clip the result to
the interval `[0, 1]`.

The runner preserves any explicit inference override stored in the checkpoint
but replaces evaluation batch size and MC sample count with the fixed OOD
values. Every angle uses the same evaluation seed, giving a controlled
comparison across rotations.

### Metrics

For both MC and posterior-mean probabilities, each angle stores:

- accuracy;
- negative log-likelihood (`nll`);
- predictive entropy mean and standard deviation;
- mean top-class confidence; and
- equal-width top-class expected calibration error (`ece`).

Probability matrices must be finite, have shape `(10000, 10)`, and have rows
that sum to one within tolerance.

Each angle additionally records primary-MC changes from zero degrees:

- `mc_accuracy_drop`: baseline accuracy minus rotated accuracy;
- `mc_nll_increase`: rotated NLL minus baseline NLL; and
- `mc_entropy_change`: rotated entropy mean minus baseline entropy mean.

### Output and logging

The result is written inside the source MNIST directory:

```text
MNIST_RUN_DIR/
├── checkpoint.json
├── weights.npz
├── history.json
└── ood_results.json
```

The checkpoint and history are only read. Re-running OOD evaluation atomically
replaces `ood_results.json` at that location.

The runner logs source loading, one concise MC/mean summary per angle, and the
destination file. It does not emit per-image predictions.

## Linear-Gaussian experiment

[`experiments/linear_gaussian.py`](../experiments/linear_gaussian.py) is a
fixed one-shot calibration experiment. Its only routinely edited value is:

```python
OUTPUT_DIR = Path("runs/linear_gaussian")
```

Unlike MNIST, the scientific and numerical settings are intentionally grouped
in the private immutable `_Protocol` rather than exposed as routine experiment
options.

### Fixed protocol

| Area | Setting | Value |
| --- | --- | --- |
| Shape | Dimension | `8` |
| Data | Training samples | `256` |
| Data | Test samples | `512` |
| Data | Batch size | `64` |
| Data | Collinear active rank | `4` |
| Model | Prior standard deviation | `1.0` |
| Model | Output residual variances | `(1e-2, 1e-1)` |
| Model | Stage A hidden residual variance | `1.0` |
| Model | Stage B hidden residual variance | `1e-2` |
| Targets | Production target variance | `1e-3` |
| Inference | Steps | `20` |
| Inference | Mean learning rate | `0.1` |
| Inference | Log-variance learning rate | `0.05` |
| Inference | Initial latent variance | `1e-8` |
| Updates | M-steps per batch | `16` |
| Updates | Active mean learning rate | `5e-2` |
| Updates | Active log-variance learning rate | `0.5` |
| Convergence | Maximum epochs | `2000` |
| Convergence | Delta tolerance | `1e-6` |
| Convergence | Patience | `5` epochs |
| Usability | Numerical-floor tolerance | `1e-5` |
| Usability | Plateau relative change | `0.2` |
| Seeds | Data / network / training | `20260806 / 7 / 11` |

Protocol construction validates positive values, exact minibatch divisibility,
even training size for paired inputs, and a collinear rank strictly below the
full dimension.

### The 24-cell grid

The grid is the cross-product of:

- two stages: `A_output`, `B_hidden`;
- three input cases: `independent`, `duplicate_agree`, `collinear`;
- two output residual variances: `1e-2`, `1e-1`; and
- two target-variance modes: `matched`, `production`.

Each cell has a stable identifier such as:

```text
B_hidden__independent__b0p01__yv_matched
```

Input cases are constructed as follows:

| Case | Construction |
| --- | --- |
| `independent` | Every row is sampled independently. |
| `duplicate_agree` | Half as many base inputs are sampled and every input row is repeated twice; observations follow the same mapping with independently sampled observation noise. |
| `collinear` | Only the first four input coordinates vary; the remaining coordinates are zero in training and test data. |

The same seeded true weight matrix is used throughout the controlled protocol.

### Stage semantics and freezing

The synthetic model contains one hidden and one output mapping with identity
activation.

| Stage | Learned layer | Frozen layer | Data behavior |
| --- | --- | --- | --- |
| `A_output` | Output layer | Hidden layer fixed to identity | Hidden noise is applied before the true output mapping. |
| `B_hidden` | Hidden layer | Output layer fixed to identity | The true hidden mapping is followed by output noise. |

The BPCN configuration uses a constant unit prior, Gaussian likelihood, mean
output estimator, zero latent perturbation, and unit KL scales. Learning rates
for the frozen layer are exactly zero. The frozen layer is initialized to an
identity mean and the minimum supported weight log variance. After training,
its mean and log variance are required to be byte-for-byte unchanged.

The exact reference treats the composed data as a linear mapping with its
effective Gaussian noise covariance. It stores full posterior precision and
covariance, posterior mean, diagonal covariance, row covariance blocks,
inverse diagonal precision, the design Gram matrix, and noise covariance.

Target variance mode affects the BPCN batch target moments:

- `matched` uses the cell's output residual variance.
- `production` uses the fixed `1e-3` production value.

### Training and convergence

Each cell uses one deterministic sample permutation, divided into four fixed
batches and reused each epoch. Network updates receive sequentially split
training keys.

After each epoch, the runner measures the maximum absolute change in the active
layer's mean and log variance. It normally stops after both remain below
`1e-6` for five consecutive epochs, or at 2,000 epochs. The last five epoch
deltas are retained in `history_tail`.

Cell status is:

- `COMPLETE` when the final deltas satisfy the convergence tolerance;
- `NOT_CONVERGED` when the epoch limit is reached while still above it; or
- `NON_FINITE` when either tracked delta becomes non-finite.

Non-finite cells do not receive calibration or stationarity metrics.

### Cell metrics

For usable trained cells, `CellMetrics` records:

- relative posterior-mean error;
- relative diagonal-variance error;
- error relative to the diagonal-KL optimal variance;
- 95% marginal coverage of the exact mean;
- average learned and exact variances and their ratio;
- total BPCN and exact precision;
- BPCN and exact predictive NLL;
- prior-retention error on unobserved collinear coordinates; and
- learned and exact mean variance on those unconstrained coordinates.

`StationarityMetrics` records:

- aggregate mean and log-variance gradient residuals;
- their norms relative to data-gradient norms;
- raw, absolute, exposure-weighted, and relative exposure-weighted variance
  residuals;
- the discrepancy in the predictive-variance relationship; and
- one-batch mean/log-variance drift used to decide whether residual diagnostics
  are locally interpretable.

A nonconverged cell may still be marked usable as `AT_NUMERICAL_FLOOR` when its
worst final delta is below `1e-5` and the retained trend changes by less than
the `0.2` plateau threshold. Otherwise it is `STILL_MOVING`. A non-finite cell
is never usable.

### Calibration gates

| Gate | Source population | Passing condition |
| --- | --- | --- |
| `G_CAL_MEAN` | Independent inputs | Relative mean error at most `0.05`. |
| `G_CAL_VAR` | Independent inputs | Relative variance error at most `0.10`. |
| `G_CAL_COVERAGE` | Independent inputs | 95% coverage from `0.90` through `0.99`. |
| `G_PREC_DIRECTION` | Duplicate-agree versus independent | BPCN/exact precision-gain ratio from `0.5` through `2.0`. |
| `G_PRIOR_RETENTION` | Data-free collinear coordinates | Relative prior-retention error at most `0.10`. |

Gates are evaluated separately for each stage, output residual variance, and
target-variance mode. A missing metric produces `passed: null`, not a pass.

Final classification is driven by the decisive Stage B cells:

| Classification | Meaning |
| --- | --- |
| `INCONCLUSIVE` | At least one Stage B cell is not a usable fixed point. |
| `CALIBRATED` | Mean and variance calibration gates pass in all Stage B slots. |
| `MEAN_ONLY` | Mean gates pass in all Stage B slots, but variance gates do not. |
| `NOT_CALIBRATED` | Stage B mean calibration does not pass across all slots. |

Coverage, precision-direction, and prior-retention gates remain important
reported diagnostics, but they do not change the four-way classification in
the current implementation.

Before running the grid, the built-in sanity check confirms:

- exactly 24 unique cells;
- exact-posterior reduction to the prior with no data; and
- exact posterior covariance independence from target values for a fixed
  design.

### Output and logging

The experiment writes exactly one artifact:

```text
OUTPUT_DIR/
└── results.json
```

It contains schema version, experiment name, complete protocol, sanity values,
all cell records, gate definitions, evaluated gates, and final classification.
There is no checkpoint or resume path.

The runner logs one concise line per cell with progress, cell ID, epoch count,
status, and available mean/variance error. The final line reports the output
path and classification.

The output directory must be missing or empty. A populated directory is
rejected rather than overwritten.

### Shared JSON behavior

[`experiments/_artifacts.py`](../experiments/_artifacts.py) provides

- dataclasses to mappings of declared fields;
- enums to their values;
- paths to strings;
- tuples and lists to JSON arrays;
- NumPy arrays to nested lists; and
- NumPy scalar values to native scalar values.

Mapping keys are converted to strings. Non-finite Python floats are rejected,
and JSON output uses `allow_nan=False`. Output is indented, key-sorted, newline
terminated, flushed, synchronized, and atomically moved into place.

Set `MNIST_RUN_DIR` to the completed MNIST directory, then run:


### Programmatic separation of computation and saving

The experiment modules keep computation and artifacts separate:

```python
from experiments.mnist import MNISTExperimentConfig, run, save_run
```

## Failure modes and troubleshooting

### Configuration fails immediately

Configuration dataclasses validate themselves. Check positive dimensions,
tuple lengths, activation names, initializer/prior/likelihood choices,
learning-rate signs, sample counts, and strictly positive residual and target
variances. The exception message names the invalid field or incompatible
values.

### Categorical inference or training reports missing class indices

Categorical output energy requires `Targets.class_indices`. Construct batches
through `iter_minibatches` or populate `Batch.class_indices` explicitly.

### A training epoch cannot be summarized

`EpochMetricsAccumulator.summary()` rejects an empty epoch. In the MNIST
runner, this indicates that the training split is smaller than one full batch
or that minibatch iteration produced no batches.

### Evaluation reports an empty split or invalid batch size

`predict_split` and `evaluate_split` require at least one example and a
positive resolved batch size. Partial final batches are supported by internal
padding, so evaluation data does not need to divide evenly.

### The MNIST or linear-Gaussian output directory is rejected

Both one-shot training runners refuse a directory containing any entry. Select
a new path or deliberately move the existing run elsewhere. They do not
silently merge or overwrite runs.

### OOD source validation fails

Confirm `MNIST_RUN_DIR` contains a checkpoint created by the current full-MNIST
runner. Required metadata includes the supported experiment/variant identifiers
and exact full ten-class dimensions and sample counts.

### Checkpoint loading fails

The directory must contain both `checkpoint.json` and `weights.npz`. Check the
schema version, exact manifest keys, exact NPZ array names, layer shapes,
residual variances, prior values, and finiteness. Current loading intentionally
rejects ambiguous or older layouts.

### Non-finite values appear

Training layer metrics expose `finite` and clamp fractions. Epoch summaries
combine those into `all_finite`. The linear-Gaussian runner classifies a cell
with non-finite epoch deltas as `NON_FINITE`; its detailed metrics are omitted.
The shared JSON writer also refuses to serialize non-finite floats.

### The first call is much slower than later calls

Training and evaluation use JIT compilation with static configuration and
shape information. The first call for a new architecture, output mode, batch
shape, or static evaluation configuration includes compilation work. Reusing
the same shapes and static metadata reuses compiled paths.

### Logs are less detailed than older runs

The current logging surface is intentionally concise. For deeper inspection,
use `BatchStepResult.e_step_metrics`, `layer_metrics`, `energy_after`, saved
epoch summaries, OOD per-angle records, or linear-Gaussian stationarity fields
instead of adding per-batch console output.

## Verification and tests

The environment-level checks for this implementation are compilation and
synthetic/unit tests. They do not substitute for executing the complete MNIST,
OOD, or 24-cell linear-Gaussian production protocols.
